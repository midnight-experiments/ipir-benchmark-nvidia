# Patches to the vendored IPIR+SP crates

Applied to `../vendor/ipir-sp/` from that folder with `patch -p1 < ../../patches/<file>`; the copy in this repository
already has them applied.

| Patch | Crate, function | What it changes |
|---|---|---|
| 0001 | `ipir-native-client`, `NativePublicSetup` | Adds `new_without_columns`: the setup identifier hashes the rows but not the column count, under its own domain tag (`/umbradb-without-columns-v1/`), so a table can gain column blocks and the masks and packing matrices of the blocks it has stay the same. `new` is unchanged. Its test: `cargo test --release -p ipir-native-client setup_without_columns`. |
| 0002 | `reinspiring`: `LiftContext::prepare_public_dot` and `public_dot`, `decompose`, `tau_coeffs`, `aggregate_masks`, `compile_fast`, `NativeMatrix::from_blocks`, and the new module `lazy_ntt` | Makes the CPU build of a column block faster, with every output word the same. `public_dot` runs its own number-theoretic transform (`lazy_ntt.rs`) on spiral-rs's tables with Shoup products, reconstructs the CRT without division, and allocates nothing per call. A collapse chain step evaluates its two auxiliary primes in parallel. `decompose` works in i64, and `tau_coeffs` permutes the coefficients directly when d and q are powers of two. The ring FFTs of compilation and aggregation write each stage into a reused scratch row, the gadget digits move into the packing matrix, and the validation scan, row allocation and widening run in parallel. The patch also adds one `#[doc(hidden)]` read-only accessor, `NativePreprocessed::matrix()`, which `../bench/src/bin/pack_digest.rs` uses to hash the compiled matrix. Its tests: `cargo test --release -p reinspiring -p ipir-sp`, whose unit tests compare the transforms, the reconstruction, `public_dot`, `decompose` and `tau_coeffs` with their definitions, and `pack_digest`, whose digests equal those of the unchanged arithmetic with only the accessor added. [`0002-faster-block-compile.md`](0002-faster-block-compile.md) explains each change, why the output stays the same, and the measurements. |
| 0003 | `reinspiring`: `NativeSetup`, `LiftContext`, `PreparedPublicDot`, `aggregate_masks` | Read-only `#[doc(hidden)]` accessors for a GPU build of a column block: the gadget masks, the aggregation of the hint masks, the prepared transforms and the auxiliary primes. No computation changes. `../bench/src/bin/gpu_build_prep.rs` uses them to prepare the GPU build's tables and the CPU's stage outputs. The stock build (`../build-stock.sh`) reverses it together with patch 0002. |

The benchmark builds every table with `new_without_columns` and seed = snapshot = 32 zero bytes, as the design does.
